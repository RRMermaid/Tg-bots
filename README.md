# Налегке
Самостоятельный Telegram-бот на Python и PostgreSQL. Анкета под цель
похудения, удержания или набора, свободный текст еды, приблизительные КБЖУ,
вес, дневная и недельная аналитика, напоминания и трёхмесячный тестовый доступ.
Salebot и другие конструкторы не используются.

## Запуск
Нужны Python 3.12, PostgreSQL и токен вашего Telegram-бота.
OpenAI API необязателен для ручного ввода калорий и обычных напоминаний.

```bash
git clone https://github.com/RRMermaid/Tg-bots.git
cd Tg-bots
git checkout codex/nalegke-rebuild
cp .env.example .env
```

Заполните `.env` приватно. Не публикуйте ключи в чате, логах или GitHub.

### Через Docker Compose
Укажите `TELEGRAM_BOT_TOKEN`, `OPENAI_API_KEY` (для оценки еды),
`POSTGRES_PASSWORD` и `ADMIN_ID` (Telegram ID владельца для уведомлений о
новых пользователях и завершении тестовых периодов). Узнать ID можно командой
`/myid`. База находится в постоянном томе `diary-data` и не публикуется в интернет.

```bash
docker compose up -d --build
docker compose logs --tail=50 bot
```

### С существующей PostgreSQL
Укажите `DATABASE_URL`. Можно также использовать `PGHOST`, `PGPORT`,
`PGDATABASE`, `PGUSER`, `PGPASSWORD`.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m db
python app.py
```

Старый запуск `python Nalegke-bot.py` также поддерживается. `bot.py` относится
к другому боту (регистрация поездки), а не к «Налегке».

До первого запуска на старой базе сохраните резервную копию. Миграции
добавляют поля/таблицы и сохраняют существующие дневники, но реальная
серверная схема пока не предоставлена. Не запускайте две версии с одним
Telegram-токеном. Новые экземпляры с общей базой защищены advisory lock;
это не остановит прежний код или сервис, не использующий этот механизм.

## Использование
1. `/start` — знакомство, контакт (необязательно), город, цель и анкета.
2. Напишите «2 яйца и 1 яблоко» или «09:00 2 яйца; 13:00 суп 300 мл».
3. Запись сохраняется сразу. Кнопка **Исправить** заменяет её без дубля.
4. Для вчерашней еды: «вчера 21:00 ужин».
5. Вес: `/weight 80,2` либо просто число после анкеты.

Остальные команды:

| Команда | Что делает |
| --- | --- |
| /report или /analyze_day | Список еды, КБЖУ и поддерживающий итог дня |
| /week | Анализ последних семи дней |
| /progress | Сравнение двух недель по записанным продуктам, интервалам и весу |
| /patterns или /recommendations | Рекомендации и наблюдаемые связи режима, еды и веса |
| /timezone | Изменить пояс без привязки к времени сервера |
| /reminders 08:30 21:15 | Время утреннего взвешивания и вечернего отчёта |
| /pause и /resume | Выключить/включить напоминания |
| /profile | Изменить анкету |
| /cancel | Прервать анкету, сохранив дневник |
| /last_notifications | Свои последние отправленные напоминания |
| /myid | Показать Telegram ID для настройки ADMIN_ID |
| /help | Примеры и справка |

Вода: «вода 250 мл» либо «вода 0,5 л». Вода сохраняется отдельно и не
перезапускает интервал между приёмами пищи. Без количества бот уточняет объём.

## Что хранится
PostgreSQL хранит профили, выбранные цели и направления поддержки,
ограничения, расчётный коридор, пробный доступ и будущие подарочные/промо-
доступы, IANA-пояса, время напоминаний, текущий шаг анкеты, приёмы,
названия/оценки количества продуктов, КБЖУ, исходный текст, воду, вес и
журнал отправок. Время еды — TIMESTAMPTZ. Суточные выборки используют
границы местных суток, включая переходы летнего времени.

Ранее сохранённые `tz_offset` остаются доступными для чтения. Их точность
относительно старого сервера неизвестна, поэтому напоминания прежним
пользователям начинаются после явного выбора пояса через /start или /timezone.

## Расход OpenAI
- Оценка еды: один ограниченный запрос на каждый приём; без истории чата.
- Ручные калории, утро, интервалы, вес, недельный анализ и /progress: без OpenAI.
- Вечерний анализ: только итог текущего дня, до 12 описаний и агрегаты 14 дней.
- Контекст отчёта ограничен 6000 символами; ответы — отдельными лимитами.
- Новых вызовов модели при повторной доставке сообщения с уже созданным
  черновиком нет. Неудавшийся запрос может быть повторён пользователем.
- На одно сообщение — до 8 приёмов пищи, до 1500 символов на приём.
- Модель задаётся OPENAI_MODEL_ID; исходное значение — gpt-4o-mini.
- Поддержка и расчётный коридор не являются медицинским назначением.

Цена отдельного запроса не растёт с количеством лет дневника. Суммарная
стоимость зависит от количества записей и запрашиваемых отчётов.
Записи БЖУ с неизвестными значениями не выдаются за точные нули.
Разбор JSON дополнительно проверяет типы, диапазоны и завершённость ответа.

## Напоминания и перезапуски
Раз в 30 секунд бот читает актуальные настройки и последние приёмы из SQL.
После перезапуска расписание восстанавливается из этих данных.
Утреннее сообщение отправляется в первые 15 минут выбранного времени,
вечернее — в первые 30. Пропущенные давно уведомления ночью не догоняются.
После супа, яиц или лёгкого приёма ориентир составляет два часа, после плотного
приёма — три. Если рассчитанное время следующего приёма оказывается менее чем
за два часа до вечернего отчёта, отдельное напоминание не отправляется.

Отправка сначала получает уникальную SQL-отметку. Это предотвращает повтор
после перезапуска или параллельного вызова. Telegram и PostgreSQL не имеют
общей транзакции: при падении между отметкой и отправкой или неоднозначном
сетевом сбое сообщение может быть пропущено. Автоматического повтора нет,
чтобы не создавать дубли; ошибка фиксируется в notification_claims.
Записи еды сохраняются атомарно отдельно от отправки ответов.

## Аналитика без причинных выводов
КБЖУ по тексту приблизительны. Если порция не указана в граммах, штуках или
понятной бытовой мере, бот сначала задаёт уточняющий вопрос. Связи продукта с изменением веса не доказывают,
что продукт «вызывает» похудение или привес. Сравниваются также пары продуктов в одном приёме пищи. Для сравнения нужны хотя бы
три дня с продуктом/сочетанием и три без него, с весом в соседние утра.
Ручные калории без состава в сравнения продуктов не попадают.
Пропущенные записи не означают отсутствие еды. Показатели разнообразия
считаются по записанным нормализованным названиям.

Для связи регулярности и веса день считается достаточно заполненным при трёх
и более приёмах. Сравнение появляется только при наличии минимум трёх
регулярных и трёх нерегулярных дней с весом в соседние утра.

## Доступ и будущая оплата
Тестовый период начинается после завершения новой анкеты и длится три
календарных месяца. После окончания дневник сохраняется, а рабочие функции
закрываются до продления. Таблица `access_grants` поддерживает будущую
подписку, промокоды, подарочные периоды и ручной доступ без изменения профиля
или истории пользователя. Платёжный провайдер пока не подключён.

## Проверки
```bash
pip install -r requirements-dev.txt
ruff check .
pytest -q
```

Для SQL-проверок задайте TEST_DATABASE_URL на отдельную базу с именем,
оканчивающимся на `_test`. GitHub Actions поднимает PostgreSQL 16 и
выполняет все проверки. На Linux под обычным пользователем тесты также могут
использовать временную PostgreSQL через pgserver. Без тестовой базы SQL-тесты
локально пропускаются, а в CI отсутствие базы считается ошибкой.

Реальный Telegram, OpenAI API и существующая серверная база проверяются
отдельно при подключении окружения. Тесты не отправляют сообщения реальным
пользователям и не обращаются к платному OpenAI API.
